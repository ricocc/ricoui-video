# 新增组件实操指南

面向在 RICOUI Video 仓库里新增一个可安装、可预览、有文档、有测试的 registry 组件。示例以当前仓库真实结构为准,贯穿示例假设新增一个原创组件 `browser-zoom`(分类 `screens`)。

CONTRIBUTING.md 是简版清单;本文是展开版,两者冲突时以代码现状为准。

---

## 0. 先决定:放进哪个目录

仓库里 `registry/` 下有三个组件目录加一个 metadata 目录,分工是固定的:

| 你要做的事 | 去哪里 | 额外动作 |
| --- | --- | --- |
| **全新原创**的场景、动画、过渡 | `registry/ricoui/<slug>/` 新建 | 见下文各节 |
| 修改来自 SnapCN 的组件的**实现** | 原地改 `registry/snap-cn/<slug>/`,不要挪目录 | 把 slug 加进 `registry/metadata/components.ts` 的 `modifiedSnapCnComponents` |
| 只改上游组件的文案、文档、品牌 | 同上 | **不要**加 `modified`(该集合只记实现变更) |
| 新增底层 UI primitive / 主题能力 | `registry/snap-cn-ui/` | 动了 `core/theme.ts` 必须同步 `app/globals.css`,`pnpm run check:tokens` 会校验两者一致 |
| 只调整设计系统 token | `registry/snap-cn-ui/core/theme.ts` + `app/globals.css` | 同上 |

**红线:不要把新的原创场景塞进 `registry/snap-cn/`。** 三个后果:

1. 出处标错。组件页的 "RICOUI / Adapted from SnapCN / SnapCN" 标签来自 `registry/metadata/components.ts`:snap-cn 与 snap-cn-ui manifest 里的每个条目都会被打成 `source: "snapcn"`,新场景放进去会显示成 SnapCN 的组件。
2. 上游对比被污染。`snap-cn/` 保持和上游同构,是为了以后 diff / 同步 upstream 时不用在一堆原创文件里筛。
3. 违反仓库既定结构(`DOCS/RICOUI Video 仓库完整改造提示词.md` 第八、九节):按**来源**分目录,不按语言、不按 modified 状态再拆。

`snap-cn-ui` 只放"会被别的组件当积木用"的东西:`core/`(timeline、theme、color、motion、types)和 `caret`、`input` 这样的 timeline 驱动 UI 原子。判断标准:如果一个东西只在你这一个场景里出现,它是场景的一部分,放 `ricoui/<slug>/` 里一起走;如果多个场景都要 import 它,才考虑升进 `snap-cn-ui` 并单独发一个 manifest 条目。

对外安装路径永远是扁平的 `@ricoui-video/<slug>`,用户完全感知不到上面这些目录。命名空间配置在 `components.json`:

```json
"registries": {
  "@ricoui-video": "https://video.ricoui.com/r/{name}.json"
}
```

## 1. 一个组件在仓库里的全部化身

新增一个组件,下面每一行都要落到一个具体文件。漏掉任何一行,都有对应的坏结果(见第 11 节的坑表)。

| 化身 | 位置 | 谁消费它 |
| --- | --- | --- |
| 组件源码 | `registry/ricoui/<slug>/index.tsx` | 构建、站点预览、`shadcn add` 拷给用户的正是它 |
| 定制器配置 | `registry/ricoui/<slug>/config.ts` | customizer 控件、docs 预览、渲染 demo 三方共用 |
| 单元测试 | `registry/ricoui/<slug>/__tests__/<slug>.test.ts` | vitest |
| barrel 注册 | `registry/__index__.tsx` | 预览舞台、customizer、`render:previews` |
| Registry manifest | `registry/ricoui/registry.json` 加一个 item | `pnpm run registry:build` → `public/r/<slug>.json` → 用户安装 |
| 出处 metadata | `registry/metadata/components.ts` | 组件页来源标签(**原创组件不用动它**,见第 6 节) |
| 画廊数据 | `lib/gallery-data.ts` 的 `GALLERY_ITEMS` | `/docs/components` 画廊、组件计数、`llms.txt` |
| 文档页 | `content/docs/<category>/<slug>.mdx` + 同目录 `meta.json` | fumadocs 侧栏与页面 |
| 演示 mp4(可选) | `lib/rendered-demos.tsx` + `public/demos/<slug>.mp4` + `lib/demo-manifest.json` | 文档页、画廊卡片的视频预览 |

## 2. 组件代码:`registry/ricoui/<slug>/index.tsx`

写之前先读两份仓库内规则(CLAUDE.md 有摘要,完整版在 `.claude/skills/`):

- **design-system**:配色、边框、阴影、圆角、字体栈怎么取。
- **motion-quality**:对文字做 scale/transform 动画前必读,每条规则都是渲染帧上量出来的坑。

硬性约束:

- **一切动画由帧驱动**:`useCurrentFrame()` + `interpolate()` + `spring()`。禁止 `setTimeout`、禁止 CSS keyframes——渲染是逐帧截图,时间轴必须是当前帧的纯函数。
- **颜色走设计系统**:组件接受 `theme?: Partial<SnapCnTheme>` 和 `mode?: "light" | "dark"`,内部用 `useSnapCnTheme` 解析。需要动画的颜色用 `mixOklch` 插值,写**具体色值**——`var(--token)` 在 Remotion 渲染里不存在,渲染产物没有你站点的 CSS。
- **对文字做 scale 时**:scale 的原点钉在基线上(用真实字体度量测,别拿 line-height 猜);`text-rendering: geometricPrecision`;`will-change: transform` 只在 `getRemotionEnvironment().isRendering` 为 false(即 Player)时开;缓动曲线别用 quint/expo 这类把收敛拖成五帧静止的形状。
- **把调度逻辑写成导出的纯函数**。看 `registry/snap-cn/status-cycle/index.tsx` 的做法:`statusAt()`、`chipAt()`、`settle()` 都是无副作用的帧 → 状态函数,组件只是把它们画出来。这样测试才有东西可测(第 8 节)。

依赖声明(进 manifest 时用,第 5 节):用了 Remotion 就有 `remotion`;用 `@remotion/google-fonts` 加载字体就加它;组合 snap-cn-ui 的 primitive 时加 `registryDependencies`(如 `https://video.ricoui.com/r/snap-cn-ui.json`、`https://video.ricoui.com/r/input.json`)。

## 3. config:`registry/ricoui/<slug>/config.ts`

`ComponentConfig` 类型定义在 `lib/customizer-config.ts`。以 `status-cycle` 的真实配置为样板:

```ts
import {
  type ComponentConfig,
  FONT_WEIGHT_OPTIONS,
  FPS,
  H,
  W,
} from "@/lib/customizer-config";

export const browserZoomConfig: ComponentConfig = {
  componentName: "BrowserZoom",              // 生成代码片段用的 PascalCase 名
  importPath: "@/components/ricoui/browser-zoom", // 文档 snippet 的 import 语句
  controls: {
    url: { type: "text", default: "ricoui.video", label: "URL" },
    zoomFrames: { type: "number", default: 45, min: 12, max: 90, step: 1, label: "Zoom length" },
    chromeColor: { type: "color", default: "#faf9f6", label: "Chrome" },
    // …text | image | number | number-input | color | select | boolean 七种控件
  },
  durationInFrames: 150,   // 必须罩住完整叙事弧(见下)
  fps: FPS,                // 30
  compositionWidth: W,     // 1280
  compositionHeight: H,    // 720
};
```

三个容易错的点:

1. **颜色默认值必须写 token 解析后的具体值**(如 `#3577e0`),并注明它对应哪个 token、哪个 mix——`status-cycle/config.ts` 头部注释就是范本。`pnpm run check:tokens` 只对 `theme.ts` 与 `globals.css`,**不覆盖 config 文件**,token 改了要手动同步这里。
2. **`durationInFrames` 要覆盖整个弧**:入场、每步节拍、收尾停顿。收尾拍(point payoff)排在晚帧的组件,同时要去 `registry/__index__.tsx` 把 slug 加进 `MIN_SPEED_ONE`(带一行注释说明 payoff 在第几帧,照抄现有条目的格式),否则 customizer 里 speed < 1 时结局永远演不完。
3. `speed` 控件不用自己加——barrel 会把 `SHARED_CONTROLS` 合进每个 config。

## 5. manifest:`registry/ricoui/registry.json`

手动加一个 item(`shadcn build` 读根 `registry.json` 的 `include`,把三个子 manifest 合并、内联源码、写出 `public/r/<slug>.json`):

```json
{
  "name": "browser-zoom",
  "type": "registry:component",
  "title": "Browser Zoom",
  "description": "A browser chrome that dollies from address bar to page content — one sentence, concrete, what it looks like.",
  "dependencies": ["remotion", "@remotion/google-fonts"],
  "files": [
    {
      "path": "browser-zoom/index.tsx",
      "type": "registry:component",
      "target": "components/ricoui/browser-zoom.tsx"
    }
  ]
}
```

- `path` 相对本 manifest 所在目录(即 `registry/ricoui/`);有辅助文件就多列几条(参照 `snap-cn-ui/input` 的两文件条目)。
- `target` 决定源码落进用户项目的路径,`importPath`(第 3 节)必须和它一致。snap-cn 层约定 `components/snap-cn/<slug>.tsx`;ricoui 原创目前还没有先例,**建议 `components/ricoui/<slug>.tsx`,首个组件落地时定下后保持一致**。
- `registryDependencies` 用完整 URL 指向本站 `/r/*.json`(参照 `answer-stream` 条目),依赖 shadcn 自带 `utils` 时写 `"utils"`。
- **不要对任何 `registry*.json` 跑 formatter**——会把整个文件重排,你的 diff 会淹没在几百行噪声里。

## 6. metadata:`registry/metadata/components.ts`

**原创组件:什么都不用做。** `getComponentSource()` 对不在 snap-cn / snap-cn-ui manifest 里的名字自动 fallback 成 `source: "ricoui"`,组件页会正确显示 "RICOUI" 标签。

只有一种情况要动它:你**修改了上游组件的实现**,把 slug 加进 `modifiedSnapCnComponents`,标签从 "SnapCN" 变 "Adapted from SnapCN"。改文案、改文档不算。

## 7. 画廊与文档

**`lib/gallery-data.ts`**(注意 `name` 是展示名不是 slug,`href` 是文档路径):

```ts
{
  name: "Browser Zoom",
  description: "A browser chrome that dollies from the address bar into the page — …",
  category: "screens",
  href: "/docs/screens/browser-zoom",
},
```

`category` 只能取 `GALLERY_CATEGORIES` 里已有的 id(`text` / `captions` / `logos` / `screens` / `social` / `scenes` / `ai-input`),对应 `content/docs/` 下的同名目录。不要为单个组件开新分类。

**文档页 `content/docs/screens/browser-zoom.mdx`**,结构照抄现有页(范本:`content/docs/scenes/status-cycle.mdx`):

## 8. 测试

**组件测试** `registry/ricoui/browser-zoom/__tests__/browser-zoom.test.ts`:测的是第 2 节导出的调度纯函数,不渲染组件。照 `status-cycle.test.ts` 的路数,每条测试对应一个会真实翻车的行为:

```ts
it("swaps on the frame the hold expires, not the one after", () => {
  expect(stepAt({ frame: 23, ...SCHEDULE })).toBe(0);
  expect(stepAt({ frame: 24, ...SCHEDULE })).toBe(1);
});

it("stops at the last step instead of running off the end", () => {
  expect(stepAt({ frame: 10_000, ...SCHEDULE })).toBe(3);
});
```

值得写的断言类型:边界帧的取值(23/24 这种)、超长 frame 的 clamp、单调性(帧前进状态不倒退)、空输入不炸。

**`lib/__tests__/registry-integrity.test.ts` 会替你把三种漂移**(manifest 有但没 build → 404;build 了但 manifest 没有 → 装的是没人在维护的源码;有文档页但装不了)。三个 tier 的 manifest(snap-cn、snap-cn-ui、ricoui)它都读,原创组件和上游衍生组件受同样的检查,不需要额外动作。

**`pnpm run check:tokens`**:只有动了 `registry/snap-cn-ui/core/theme.ts` 或 `app/globals.css` 才需要跑。

## 9. 预览:live Player,以及什么时候不信它

默认路线:**docs 预览与 customizer 走 live `<Player>`**(React 在浏览器里按 `requestAnimationFrame` 实时重渲染),零额外工作。

Player 不是视频:30fps 合成在 120Hz 屏上每帧要恰好撑满四次刷新,超了 ~8ms 预算的帧不是被丢掉而是被播错时长——肉眼读作卡顿和抖动。对"长时间对文字做 scale"的场景尤其严重,而这正是标题类动画的形态。所以:

- **加入 `lib/rendered-demos.tsx` 的 `RENDERED_DEMOS` 只有一个正当理由:live 预览失真**(慢速 scale 文字、逐帧换图、一帧内画十几次的运动模糊之类)。不要因为"更好看"就加——每个条目都是一份要跟着组件改动永远重渲染、重提交的 mp4。
- 目前 barrel 里**所有**组件都在列表里(后半段是"为覆盖率而渲染"的一批),新组件默认也应该进,保持"站点不启动 Remotion 也能放演示"的现状;真觉得某条不划算,删掉那行即可,页面会自动退回 live Player。
- **代价是硬义务:改了 `RENDERED_DEMOS` 里的组件,同一次提交里重渲染**:

```bash
pnpm run render:previews --only browser-zoom
```

脚本(`scripts/render-previews.mts`)从 `RENDERED_DEMOS` 自动注册合成(`src/remotion/previews-root.tsx`),用 barrel 折叠后的默认 props 复现 `PreviewStage`,写出 `public/demos/<slug>.mp4` 并更新 `lib/demo-manifest.json`(文件字节哈希,作为 `?v=` 缓存击穿)。mp4 是**提交进仓库**的,生产构建不允许依赖 headless Chrome。过期的演示比卡顿的演示更糟——没有任何构建期检查会提醒你。

## 10. 构建与验证

全流程命令,按顺序:

```bash
pnpm run registry:build            # 生成 public/r/browser-zoom.json
                                   # 注意:会重写全部 public/r/*.json,属正常,diff 里只审自己的条目
pnpm lint                          # biome
pnpm typecheck                     # tsc --noEmit
pnpm test                          # vitest(含 registry-integrity)
pnpm dev                           # localhost:3000 人工核对:
                                   #   /docs/screens/browser-zoom 预览、customizer 控件、
                                   #   /docs/components 画廊与计数、侧栏入口、搜索
```

改动涉及已渲染演示或主题 token 时追加:

```bash
pnpm run render:previews --only browser-zoom
pnpm run check:tokens
```

端到端验证安装(可选但推荐):`pnpm build && pnpm start` 起本地站,在一个临时 Remotion 项目里把 `components.json` 的 registry 指到 `http://localhost:3000/r/{name}.json`,跑 `npx shadcn@latest add @ricoui-video/browser-zoom`,确认文件落盘、依赖带全、import 即可用。**不要拿生产站做这个测试**——`/r/<slug>.json` 的每次抓取都被 PostHog 计为一次真实安装(转化指标)。

提交前对照 CONTRIBUTING.md 的 "Before you open a PR";PR 描述里说清改了什么、凭什么说它是对的——"看着没问题"对帧精确动画不构成结论,渲染出帧来看。

## 11. 坑表

| 症状 | 根因 | 对照 |
| --- | --- | --- |
| 文档页安装命令 404 | manifest 加了但没跑 `registry:build` | 第 10 节;`registry-integrity` 第 1 条 |
| 装进用户项目的是没人维护的旧源码 | 删了组件没清 `public/r/`(`shadcn build` 只写不删) | `registry-integrity` 第 2 条 |
| 侧栏看不到新页面 | 忘改 `content/docs/<category>/meta.json` | 第 7 节 |
| 组件页标成 "SnapCN" | 原创场景被塞进了 snap-cn 目录 | 第 0 节红线 |
| 改了上游组件没换标签 | 忘加 `modifiedSnapCnComponents` | 第 6 节 |
| speed 拖慢后结局演不完 | 晚帧 payoff 没进 `MIN_SPEED_ONE` | 第 3 节 |
| 站上演示是上个月的动画 | 改了组件没重渲染 mp4,无构建期检查 | 第 9 节 |
| 视频(渲染)里颜色对不上站内预览 | 组件里用了 `var(--token)`,渲染没有站点 CSS | 第 2 节 |
| config 色板和站点脱节 | token 改了没同步 config 的具体默认值(`check:tokens` 不管这里) | 第 3 节 |
| manifest diff 淹没几百行 | 对 `registry*.json` 跑了 formatter | 第 5 节 |
